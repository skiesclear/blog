Agent Skills

介绍Agent Skill，并拿nature skills作一个说明

概念

Agent skill就是大模型可以随时翻阅的说明文档。

例如：

skill.md内容

基本用法

按需加载：大模型从agent提供的skill目录列表中选择一个skill，然后agent将对应的skill.md发送给大模型。

随着skill的发展，希望skill越来越高级：

  1. 当设计金额，标注财务合规状态（涉及相关的财务规定）
  2. 涉及合同时，提示法务风险（涉及相关的法律条文）
    如果都加入到skill.md中，不仅会使skill.md变得臃肿，而且需要在不涉及这些内容的会议总结过程中也需要加载这些内容。
    这就需要做到：按需中的按需。

高级用法

Reference

当会议中真的提及到了钱，才会将财务规定加载给模型。这就是Reference干的活儿。
在instruction中新增一个财务提醒规则：

特性：条件触发，只有当模型读取完skill.md文件，判断出需要查账…时，才会加载这个相关文件

Script

让Agent Skill跑代码，做到真正的自动化

特性：Agent Skill中的代码只会被执行，不会被读取。它消耗的上下文内容几乎是0。Agent只关心脚本的运行命令，运行结果，不关心运行内容。

Agent Skill的渐进式披露(Progressive Disclosure)机制

三层：

  1. 元数据层（metadata）
    1. 包含：名称+描述
    2. 特性：始终加载
  2. 指令层（instruction）
    1. 包含：Skill.md中除名称和描述之外的内容
    2. 特性：按需加载
  3. 资源层（Resource）
    1. 包含：Reference（被读取）+Script（被执行）。 （官方有个Asset，和reference部分重叠）
    2. 按需中的按需加载

Agent Skill VS MCP

本质上都是让模型连接和操纵外部世界。但是
Anthropic：MCP connects Claude to data, Skills teach Claude what to do with data.

虽然Agent Skill也有可以有连数据的代码，但是能干并不代表适合。
MCP本质上是独立运行的程序，Agent Skill本质上是说明文档。
所以Agent Skill更适合轻量的脚本，处理些简单逻辑，但在安全性和稳定性不及MCP，很多场景下将Agent SKill和MCP结合起来做一些更工程化的工作。

Nature Skills 举例

Nature Skills是多个skill的集合

属于是一个Skill Registry包含很多skills

也就是说所有子 Skill 平级参与检索。
这样的设计被称为：扁平 Skill Registry
优点：

  • 简单
  • discovery 快
  • 每个skill独立

而且图中的skills是仓库级脚本（repository scripts），服务对象是Skill的作者，不是给Agent执行任务用的。

以nature-paper2ppt skill为例

除了通用的Skill.md, script/, references/，对剩余内容作一个介绍：

  1. agents/
    包含openai.yaml

这个通常表示：这个 Skill 内部可以定义一个专用 Agent 或 Agent 行为配置。
面向Agent运行框架，告诉框架怎么创建/配置Agent。

比如

  1. static/
    很重要，Skill 不只是文字说明，有些东西需要固定模板。

static/core/可以理解为所有 paper2ppt 任务都通用的知识规则
static/fragments/paper_type/更像是不同论文类型的提示片段（prompt fragments）

  1. manifest.yaml —— Skill 清单文件
    很关键，告诉 Skill 系统：“我是谁，我有什么”。

manifest.yaml 是给机器/框架看的“身份证 + 元数据”；SKILL.md 是给 Agent 模型看的“工作手册”。
Skill Registry 扫描1000个skills/时，不会打开所有的SKILL.md，而是先读manifest.yaml，建立索引
