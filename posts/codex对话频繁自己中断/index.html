codex对话频繁自己中断

活儿干一点总是自己断开，每次都要continue继续让它工作，贼烦

使用codex的goal模式，给agent设定一个目标，如果没完成目标，就一直运行

Goals vs prompts

正常prompts会说：执行下一步操作。
Goals指令表示：持续执行直至达成此结果。这种区别至关重要。在普通请求中，Codex 会执行当前指令，报告结果，然后等待。而对于目标指令，Codex 则拥有一个与进程绑定的持久目标。回合结束后，它可以检查当前的证据，并判断目标是否达成。如果答案是否定的，且目标仍然有效且在预算范围内，Codex 可以从最新状态继续执行。

因此，当正确的下一步行动取决于 Codex 刚刚学到的信息时，目标就显得尤为有用。例如：

/goal Reduce p95 checkout latency below 120 ms on the checkout benchmark while keeping the correctness suite green

此请求不仅仅要求更高的性能。它为 Codex 提供了一个可衡量的结果、一个验证界面和一个约束条件。Codex 可以运行基准测试，检查热点路径，进行针对性修改，重新运行基准测试，运行正确性测试套件，如果结果仍然不理想，则可以继续进行后续步骤。

How to write a Goal

一个好的Goal不仅仅是一个更大的prompt。它是一份简洁的契约，规定了 Codex 的运作方式、成功的标准以及在尚未达到目标时应该采取的措施。

最有效的目标通常包含六个要素：

  1. 结果：工作完成后应该达到的现实状态。
  2. 验证面：证明其有效性的测试、基准测试、报告、工件、命令输出或源材料。
  3. 限制条件：Codex 运行期间哪些方面不能倒退。
  4. 边界：Codex 可以使用的文件、工具、数据、存储库或资源。
  5. 迭代策略：Codex 应该如何在每次尝试后决定下一步要尝试什么。
  6. 阻塞停止条件：当 Codex 应该停止并报告在当前限制下没有可防御的路径时。
