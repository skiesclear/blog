① 3DGS 场景构建与渲染（aholo3dgs） →
② Python 控制无人机飞行 + 捕捉图片（python-controller） →
③ OpenFly-Platform 工具链（点云转换 → 语义分割 → 轨迹生成 → BEV 地图 → 指令生成）

每一步都给出可直接复制的命令。

阶段一：3DGS 场景构建与渲染（aholo3dgs）

目录：/home/yaojianhang_25/workspace/3dGS/aholo3dgs

1.1 场地视频拍摄

前置条件：一台相机（手机不行）。

拍摄要求：

  • 明亮且稳定的照明（早晨或傍晚）；
  • 相对可控的环境（静止场景最好，避免行人/车辆移动）；
  • 拍摄轨迹：形成闭环路径、缓慢且匀速行走。

产出：场地视频.mp4（一段或多段）。

1.2 Aholo 3D Studio 重建并导出 .ply

平台：https://studio.aholo3d.com/library

  1. 进入 My Projects 界面，将视频拖入 3DGS Reconstruction 界面；
  2. 选择 capture type（indoor / outdoor）；
  3. 选择构建质量（standard / professional）；
  4. 点击 create 开始构建（构建较慢）；
  5. 构建成功后进入项目，右上方 export 导出 .ply 文件（导出需要会员）。

免费账号只能用 standard 且只有 10 次机会；Pro 会员可无限 standard
并可尝试 professional。

产出：badminton_court.ply（3D 高斯点云，本例约 384 MB）。

阶段二：Python 控制无人机移动并捕捉图片（python-controller）

目录：/home/yaojianhang_25/workspace/VLA/python-controller

2.1 工作原理

drone_controller.py 用纯 Python 标准库实现一个 HTTP 长轮询控制器：

  • Python 通过 DroneController 发命令 → 浏览器页面轮询拿到后在场景中移动无人机、
    渲染五个视角（front / back / left / right / down）→ 把 base64 图片回传；
  • 碰撞事件由浏览器页面对 voxel 碰撞体做胶囊检测，异步 POST /event 回传；
  • Python 侧只用标准库，无额外依赖。

2.3 OpenFly 数据捕获适配器：openfly_bridge.py

openfly_bridge.py 在无人机控制器之上加了一层 TCP 服务，专门对接
OpenFly 的 traj_gen 节点：

  • 读取 OpenFly 配置 configs/<env>.yaml 的 thread_params，在 aim_port（9999）
    上监听 TCP；
  • 收到 path:<目录> 消息 → 设定本次轨迹的图像保存目录、重置帧号；
  • 收到 x,y,z,pitch,yaw,roll（导航坐标系）→ 转换成 aholo 坐标系
    （nav_to_aholo_pose，含 roll 偏移）→ 让浏览器执行 capture_five
    （960×540）→ 落盘为 0000XX_front.png 等五张图；
  • 首帧 000000 额外采集一张 240×135 的前向深度图
    （000000_front_depth16.png，单位厘米，用于指令生成时的遮挡/唯一性审计）；
  • 每帧写入 capture_metadata.jsonl（nav/aholo 位姿、真实相机基向量、深度元信息、
    碰撞状态、文件列表）；
  • 图像与元数据持久化写盘后才回 OK，traj_gen 收到 OK 才下发下一位姿
    （保证采集不丢帧）。

3.4 第 3 步：轨迹生成 + 图像采集（三终端协同）

这是把阶段一（渲染前端）、阶段二（Python 桥）、阶段三（traj_gen）串起来的关键步骤。

traj_gen 的工作流程：

  1. 加载 scene_data/pcd_map/<ENV>.pcd，构建 BEV 体素占用地图；
  2. 加载 scene_data/seg_map/<ENV>.jsonl 的 landmark（作为轨迹起点/终点目标）；
  3. 按 thread_params（nums=20，距离 610 m，高度 03 m）在体素网格上做
    4-DoF（前进 / 左转 / 右转 / 上升 / 下降）A* 规划，生成 20 条无碰撞轨迹，
    并把航向变化插值为 turn left / turn right 动作序列；
  4. 通过 TCP sim_ip:aim_port（127.0.0.1:9999）先发送 path:<记录目录>，
    再按 freq 逐帧发送位姿 x,y,z,pitch,yaw,roll；
  5. openfly_bridge 收到后驱动浏览器渲染并保存五视角图像（首帧含深度图），
    回 OK 后 traj_gen 才发下一帧；
  6. 全部发完后写出 pose.jsonl。

输出目录结构：uav_vln_data/<env>/<data_type>/<时间戳>/

pose.jsonl 结构：第 1 行是 trajectory（start/stop/end 位姿），中间每行一个
action（imageid / type：go straight、turn left、turn right、ascend、descend /
value / yaw / pos），最后一行是 aim_landmark（目标语义对象 + position）。

3.6 第 4 步：指令生成（instruction）

输入：3.4 采集到的轨迹目录集合；输出：tool_ws/src/ins_gen/instructions/train.json。

生成流程（三段式，目标先几何确定、不让 VLM 猜目标）：

① 生成 traj_lists（轨迹目录清单 json）

traj_lists 就是一个 JSON 数组，元素为轨迹目录的绝对路径
（没有自动生成脚本，手动列目录即可）：

② 先执行不调用模型的首帧几何唯一性审计

  • 纯几何计算，不调 VLM：检查每条轨迹首帧中目标是否可见、是否唯一
    （利用 000000_front_depth16.png 做遮挡判断），避免生成指代模糊的指令；
  • 产出详细报告 tool_ws/src/ins_gen/traj_lists/..._vla_short_train_grounding_audit.json。

③ GPT 生成 instruction

前置配置：tool_ws/src/ins_gen/gpt_api_config.json，每项为一个 API 配置：

行为与产出：

  • 并发受 Semaphore(2) 限制，逐条处理轨迹目录，结果每 10 条批量落盘；
  • 只有几何唯一且模型验证通过的样本写入 tool_ws/src/ins_gen/instructions/train.json；
    失败项写入 train_failures.json（含失败原因，便于排查）；
  • train.json 每条记录：image_path（轨迹目录）、gpt_instruction
    （如 “Descend toward the central visible edge midpoint of the left badminton court.”）、
    instruction_debug（target_context / trajectory / relative_motion 等）。

注意：gpt_generation.py 里硬编码了项目路径
traj_folder = "/home/yaojianhang_25/workspace/VLN/OpenFly-Platform/uav_vln_data"，
与 /VLM/... 是同一目录（绑定挂载），所以 traj_lists 里写哪个路径都能对上；
若项目整体迁移，需要同步修改该常量。

5. 常见问题

现象 排查
页面打开后 Python 端一直等不到前端 确认 URL 带 ?controller=http://127.0.0.1:8765，且 8765 端口的 Python 进程已 start()；curl http://127.0.0.1:8765/health 应返回 frontend_ready
改了 python-control.ts 没生效 必须 npx tsc 重新编译并重启 Vite / 强刷浏览器
场景在 RViz 里上下颠倒 修改 yaml gs_transform.axis_map 的最后一项（-y ↔ y），重新生成 PCD
traj_gen 报找不到 pcd / jsonl 检查 ENV 环境变量与 scene_data/pcd_map/<ENV>.pcd、scene_data/seg_map/<ENV>.jsonl 文件名是否严格一致
bridge 收不到位姿 确认终端 B 已打印 listening on 0.0.0.0:9999，且 yaml thread_params.aim_port 与 bridge 实际监听端口一致
轨迹全部采集很慢 每帧要等浏览器渲染 + 写盘 + 回 OK 才发下一帧，属正常同步机制；减小 nums 或降低分辨率可加速
gpt_generation.py 报 ModuleNotFoundError: aiofiles conda activate openfly && pip install aiofiles
指令全进了 train_failures.json 先看 grounding audit 报告里哪些样本几何不唯一；再查 API 配置（key / base_url / model 是否可用）
首帧没有 depth 图 确认启动 bridge 时没加 --no-front-depth；深度图只采首帧 000000_front，分辨率 --depth-width/--depth-height（默认 240×135）
