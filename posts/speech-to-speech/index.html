使用本地部署的Qwen3.8 27B FP8模型+speech项目，实现网页英语对话

介绍Speech To Speech

SpeechToSpeech官方这样介绍：

A low-latency, fully modular voice-agent pipeline: VAD -> STT -> LLM -> TTS, exposed through the core OpenAI Realtime GA event set over WebSocket and WebRTC.
其中名词有

  • VAD（Voice Activity Detection）：判断：当前有没有人在说话。
  • STT（Speech To Text）：语音转文字
  • TTS（Text To Speech）：文字转语音
  • OpenAI Realtime GA event set
    • General Availability （GA）：正式稳定版本
    • Realtime API 是 OpenAI 为实时语音设计的一套协议
  • WebSocket：一种实时双向通信协议。（目的：数据通信，延迟低）
  • WebRTC（Web Real-Time Communication）：网页实时通信技术。（实时音视频，延迟更低）

Demo 客户端到底在干什么
从 main.js 看,它走的是 OpenAI Realtime 协议(WebSocket):
1.
抓麦克风 → 音频切成小块 → base64 → 发 input_audio_buffer.append 事件
2.
收后端的 response.audio.delta 事件(base64 PCM 音频)→ 解码 → 播放
3.
收 response.audio_transcript.delta 等文本事件 → 显示字幕

Demo 里的东西 Android 原生做法 ━━━━━━━━━━━━━━━━━━━━━━━━━━━ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 麦克风采集 (getUserMedia) AudioRecord:16kHz / mono / PCM16,约 30ms 一块,base64 后发 WebSocket ─────────────────────────── ───────────────────────────────────
───────────────────────────────── WebSocket 收发 OkHttp WebSocket,连 wss(s)://你的后端/v1/realtime ─────────────────────────── ───────────────────────────────────────────────────────────────────── 播放 TTS 音频 AudioTrack:24kHz / PCM16 流式写入(Realtime 输出是 24k) ─────────────────────────── ───────────────────────────────────────────────────────────────────── Orb 界面 / 字幕 一个 Activity(Compose),按钮 + 文本列表 ─────────────────────────── ───────────────────────────────────────────────────────────────────── Settings 里的后端 URL 一个输入框,存 SharedPreferences,启动时连 ─────────────────────────── ───────────────────────────────────────────────────────────────────── 权限 只需 RECORD_AUDIO
核心代码量不大,大概:
•
RealtimeClient.kt:OkHttp WebSocket,连上后发 session.update(voice、input_audio_format: pcm16、output_audio_format: pcm16、instructions),然后按事件类型分发处理
•
AudioRecorder.kt / AudioPlayer.kt:采集和播放
•
MainActivity:UI + 生命周期管理
两个值得注意的点:
1.
打断(barge-in):用户开口时,后端(开 server VAD 的话)会发 input_audio_buffer.speech_started,这时要立刻停掉 AudioTrack 播放并可选发 response.cancel,否则会出现”自己听自己”的串音。
2.
后端地址格式:直接模式就是 http(s)://host:port → 客户端自己拼 /v1/realtime(main.js 里就是这么处理的)。如果你的后端是 HF Space 的 LB 模式,客户端还要先走 POST /api/session 拿真正的 session URL——建议先用直连模式(自部署的 speech-to- speech 服务器或直连地址),最省事。
所以你的设想成立:App = OkHttp WebSocket + AudioRecord + AudioTrack + 一个 URL 输入框,到时候填 backend 链接就能用。
